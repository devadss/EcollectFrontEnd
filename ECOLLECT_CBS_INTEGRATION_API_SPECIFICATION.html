Technical Specification

ECollect - Core Banking System (CBS) Integration API

Standard Interface Specification Document for Core Banking Software Vendors

1. Overview & Architecture

This document details the standard REST API interface for connecting the ECollect Field Collection & Digital Payment Platform with client Core Banking Software (CBS) / Cooperative Banking Systems.

Integrated Model Advantage: Provides live verification of customer installment dues, instant ledger credit for cash/UPI collections, elimination of manual end-of-day Excel entries, and automated bank reconciliation.

2. Protocol & Security Standards

  • Transport Layer: HTTPS with TLS 1.2 or TLS 1.3 encryption.
  • Data Interchange: JSON (Content-Type: application/json; charset=utf-8).
  • Network Security: Mutual Static IP whitelisting between ECollect and CBS Gateway.
  • Authentication: API Key & Client Identification Header.

Standard Request Headers

Content-Type: application/json
Accept: application/json
X-API-KEY: {{CBS_MERCHANT_API_KEY}}
X-CLIENT-CODE: {{SOCIETY_OR_BANK_CODE}}
X-REQUEST-ID: REQ202609231450001234

5. Error Codes Reference

Code Constant Description
E01 INVALID_PAYLOAD Missing mandatory fields or invalid data formatting.
E02 ACCOUNT_NOT_FOUND Account number does not exist in CBS.
E03 ACCOUNT_CLOSED_OR_DORMANT Account is closed, dormant, or blocked from collections.
E04 INVALID_AGENT Agent ID inactive or not mapped to branch in CBS.
E05 LIMIT_EXCEEDED Collection amount exceeds permissible limits.
E06 DUPLICATE_ORDER_ID Transaction order_id already exists in CBS.
E07 CBS_EOD_IN_PROGRESS CBS Day-End / BOD in progress; posting temporarily paused.
E08 REVERSAL_NOT_PERMITTED Transaction already finalized in EOD or supervisor approval missing.
E99 CBS_INTERNAL_ERROR General CBS database or ledger error.

6. CBS Vendor Deliverables Checklist

  • Provide Base URLs for UAT and Production Gateways
  • Provide API Key / Client Code / Bearer Token credentials
  • Static IP Whitelisting for mutual server firewall communication
  • 3 Test Accounts for each Product Type (LOAN, RD, DD, SB)
  • End-to-End Test Posting validation (Cash & UPI QR)
