Technical Specification

ECollect - Core Banking System (CBS) Integration API

ECollect Private Limited • Standard Interface Specification Document for Core Banking Software Vendors

1. Overview & Architecture

This document details the standard REST API interface for connecting the ECollect Private Limited (ECollect) Field Collection & Digital Payment Platform with client Core Banking Software (CBS) / Cooperative Banking Systems.

Integrated Model Advantage: Provides live verification of customer installment dues, instant ledger credit for cash/UPI collections, elimination of manual end-of-day Excel entries, and automated bank reconciliation.

1.2 Workflow 1: Real-Time Data Fetching & Live Due Calculation

Enables field representatives to search customer accounts on demand and compute live overdue amounts, accrued interest, penalty charges, and allowable payment ranges directly from the CBS engine.

[ Field Agent Mobile App ] [ ECollect Cloud Gateway ] [ Core Banking System (CBS) ] | | | | --- 1. Search (Acc No / Mobile / ID) ---> | | | | --- 2. POST /api/cbs/account-details -----> | | | (search_type, account_no, branch) | | | | -- Validates Status & KYC | | <-- 3. Return 200 OK (Profile & Balance) -- | | <-- 4. Display Account Card on Mobile --- | | | | | | --- 5. Tap "Fetch Live Due" -------------> | | | | --- 6. POST /api/cbs/installment-due -----> | | | (account_no, product_type, date) | | | | -- Runs Accrual & Overdue | | <-- 7. Return 200 OK (Live Due Breakdown) - | | <-- 8. Render Due Breakdown & Pay Tabs --- | | | | |
Step Interaction Stage API Endpoint Called Target System Data Transferred & CBS Processing
Step 1 Account Search Internal App Query ECollect Gateway Agent types Account Number (e.g. LN100200300), Mobile Number, or Customer ID.
Step 2 Account Verification POST /api/cbs/account-details Core Banking System Gateway queries CBS with search_type, account_number, and branch_code. CBS validates account is ACTIVE and belongs to the requested branch.
Step 3 Account Profile Response JSON Response (200 OK) ECollect Gateway CBS returns customer name, scheme name, current balance, opened date, assigned agent code, and collection status.
Step 4 Live Demand Computation POST /api/cbs/installment-due Core Banking System Triggered when agent views demand or initiates payment. CBS computes live accruals: installment_amount, principal_due, interest_due, penalty_charges, and total_due_amount.
Step 5 Actionable Presentation JSON Response (200 OK) Mobile App UI Mobile screen renders live amount payable with one-tap quick pay buttons: Full Due, Installment Only, or Custom Amount within min_payable_amount and max_payable_amount.

1.3 Workflow 2: Real-Time Transaction Posting & CBS Ledger Credit

Executes live collection posting for both Cash and Dynamic UPI QR payments. Guarantees instant ledger credit, idempotent protection against duplicate credits, and automated timeout status verification if network connectivity drops.

[ Customer / Agent App ] [ ECollect Cloud Gateway ] [ Core Banking System (CBS) ] | | | | --- 1. Collect Cash OR Scan UPI QR -----> | | | (Validates Cash Limits & Order ID) | | | | --- 2. POST /api/cbs/transaction-post ----> | | | (order_id, deposit_amount, agent_id, | | | branch, tran_type: 'C', upi_rrn) | | | | -- Idempotency Check | | | -- Credit Customer Ledger | | | -- Debit Agent/Bank GL | | | -- Generate Receipt No | | <-- 3. Return 200 OK ---------------------- | | | (cbs_txn_id, cbs_receipt_no, bal) | | <-- 4. Instant Thermal Receipt / SMS ---- | | | | | | [IF TIMEOUT / CONNECTION DROP]: | | | | --- 5. POST /api/cbs/transaction-status --> | | | (order_id, client_code) | | | <-- 6. Confirms Posted / Not Found -------- | | | (Prevents duplicate ledger credit) |
Step Interaction Stage API Endpoint Called Target System Data Transferred & CBS Processing
Step 1 Payment Capture App Payment Event ECollect Gateway Agent receives Cash or customer scans Dynamic UPI QR. ECollect assigns a globally unique, idempotent order_id (e.g. ORD202610011450009988).
Step 2 Real-Time Ledger Posting POST /api/cbs/transaction-post Core Banking System Gateway initiates authenticated posting payload: order_id, account_no, deposit_amount, tran_type: "C", payment_channel: "CASH"|"UPI", agent_id, branch_code, upi_rrn, and timestamp.
Step 3 CBS Ledger Credit CBS Internal DB Engine CBS Database CBS checks order_id idempotency, credits the loan/deposit account ledger, debits the agent cash holding GL or UPI settlement GL, and creates a CBS receipt number.
Step 4 Receipt & Confirmation JSON Response (200 OK) ECollect & Customer CBS returns cbs_transaction_id and cbs_receipt_no. ECollect triggers thermal receipt printing and automated customer SMS/WhatsApp receipt.
Step 5 Timeout Fallback Safeguard POST /api/cbs/transaction-status Core Banking System Network Disconnect Handling: If the HTTP connection drops before ECollect receives confirmation, Gateway calls this endpoint using order_id to verify whether CBS posted the credit before retrying.
Step 6 EOD Reconciliation POST /api/cbs/day-reconciliation Core Banking System Day-End Automated Audit: Compares total collected volume, transaction counts, and branch totals between ECollect and CBS ledgers to authorize day closing.

2. Protocol & Security Standards

  • Transport Layer: HTTPS with TLS 1.2 or TLS 1.3 encryption.
  • Data Interchange: JSON (Content-Type: application/json; charset=utf-8).
  • Network Security: Mutual Static IP whitelisting between ECollect and CBS Gateway.
  • Authentication: API Key & Client Identification Header.

Standard Request Headers

Content-Type: application/json
Accept: application/json
X-API-KEY: {{CBS_MERCHANT_API_KEY}}
X-CLIENT-CODE: {{SOCIETY_OR_BANK_CODE}}
X-REQUEST-ID: REQ202609231450001234

4. Core API Specifications

POST /api/cbs/branches

Purpose: Synchronize active branches, branch codes, and IFSC identifiers.

Request Body:

{
  "client_code": "FIN001",
  "status": "ACTIVE"
}

Response (200 OK):

  "response_code": "00",
  "message": "Branches fetched successfully",

      "branch_code": "BR001",

      "contact_number": "04952700001",
      "address": "1st Floor, Financial Towers, Calicut, Kerala",
      "is_active": true
    }
  ]
}
POST /api/cbs/agents

Purpose: Synchronize collection agents, assigned branches, CBS Origin IDs, and daily collection limits.

Request Body:

{
  "client_code": "FIN001",
  "branch_code": "ALL",
  "status": "ACTIVE"
}

Response (200 OK):

{
  "status": "SUCCESS",
  "response_code": "00",
  "message": "Agents list fetched successfully",
  "data": [
    {
      "agent_code": "AGT101",
      "agent_origin_id": "CBS_AGT_101",
      "agent_name": "Rahul Das",
      "mobile_number": "9876543210",
      "email": "rahul.das@bank.com",
      "branch_code": "BR001",
      "branch_name": "Main Branch - Calicut",
      "daily_cash_limit": 200000.00,
      "is_active": true
    }
  ]
}
Agent Code Uniqueness & Validation Rules:
  • agent_code must be unique within the client institution (client_code). ECollect enforces uniqueness per merchant partner. Two distinct institutions may use identical codes (e.g., 001), but duplicate agent codes within the same institution are rejected.
  • agent_origin_id: CBS internal Agent primary key / Employee code.
  • branch_code: Must correspond to an active branch in the Branch Master API.
  • daily_cash_limit: Maximum permissible daily cash holding ceiling (INR).

5. Error Codes Reference

Code Constant Description
E01 INVALID_PAYLOAD Missing mandatory fields or invalid data formatting.
E02 ACCOUNT_NOT_FOUND Account number does not exist in CBS.
E03 ACCOUNT_CLOSED_OR_DORMANT Account is closed, dormant, or blocked from collections.
E04 INVALID_AGENT Agent ID inactive or not mapped to branch in CBS.
E05 LIMIT_EXCEEDED Collection amount exceeds permissible limits.
E06 DUPLICATE_ORDER_ID Transaction order_id already exists in CBS.
E07 CBS_EOD_IN_PROGRESS CBS Day-End / BOD in progress; posting temporarily paused.
E08 REVERSAL_NOT_PERMITTED Transaction already finalized in EOD or supervisor approval missing.
E99 CBS_INTERNAL_ERROR General CBS database or ledger error.

6. CBS Vendor Deliverables Checklist

  • Provide Base URLs for UAT and Production Gateways
  • Provide API Key / Client Code / Bearer Token credentials
  • Static IP Whitelisting for mutual server firewall communication
  • 3 Test Accounts for each Product Type (LOAN, RD, DD, SB)
